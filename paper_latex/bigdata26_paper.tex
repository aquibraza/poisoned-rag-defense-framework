\textit{Thesis.}
RAG poisoning defenses rest on different assumptions about how poisoned passages
differ from benign ones: cross-passage embedding clustering, lexical and semantic
density, learned feature separability, or answer aggregation. Stress tests
constructed to target each assumption directly reveal distinct failure modes and
distinct tradeoffs, and no single defense family is uniformly robust.

downstream number, and because retrieval must be rerun against a corpus holding
one version of each poisoned passage, not two.

\section{Stress-Testing Methodology}
\label{sec:method}
% Budget: ~1.10 pg, contains Fig. 1 and Table II.

\subsection{Overview of the Experimental Pipeline}
Fig.~\ref{fig:pipeline} shows the pipeline: poison authoring, retrieval, defense,
generation, and metrics. Each stress operator enters at exactly one stage, and
the stage it enters at determines what its result can license.

\subsection{Evaluation Regimes}
\label{subsec:regimes}
Table~\ref{tab:evaluation_levels} defines the four regimes, what each holds
fixed, what each therefore tests, and its current completion status.

\textit{Oracle embedding and feature stress tests.} Poison representations are
modified directly in the space the defense's decision rule reads, with retrieval
membership and passage text held fixed. Establishes which statistical assumption
the rule operatively depends on; establishes no attack.

\textit{Fixed-context mutation.} Poison passage \emph{text} is rewritten and
substituted into a retrieved context whose membership and order are held fixed by
construction. Establishes that the assumption is reachable by a real passage;
establishes nothing about retrieval.

\textit{Full-retrieval replacement.} Mutated poison replaces original poison in
the corpus and retrieval is rerun under a preserved poison budget. Establishes
that the rewrite still retrieves.

\textit{Answer-generation ASR.} Generation is run on the post-defense context and
the target incorrect answer is scored. Establishes an answer-level outcome for
the cases evaluated, and only for those cases.

\subsection{Oracle Perturbations}
\label{subsec:oracle}
All four operators act on a frozen embedding space with retrieval membership and
passage text held fixed.

\textit{E1 clean-anchor interpolation.} Each poisoned embedding is interpolated
toward an assigned clean anchor,
$\mathbf{z}' = \alpha \mathbf{z}_{\mathrm{poison}} + (1-\alpha)\mathbf{z}_{\mathrm{anchor}}$,
under several anchor-assignment strategies and a sweep over $\alpha$.
\TODO{Name the anchor strategies and the $\alpha$ grid.}

\textit{MMD.} Kernel mean matching of the poisoned group toward the clean group,
with a preservation penalty controlling how far embeddings may move.

\textit{CORAL-PCA and CORAL-ridge.} Covariance alignment treating poisoned
embeddings as source and clean embeddings as target, in a reduced-rank and a
regularized form respectively.

These are not text-space attacks and not learned domain-adaptation models; they
are formal embedding-space stress tests of a similarity-based decision rule.

\subsection{GPT Targeted Mutation Families}
\label{subsec:families_mut}
Three hand-authored GPT rewrite families, one per targeted assumption. Each
family rewrites all $\Npoison$ poisoned passages of a query while preserving the
attacker's target answer.

\textit{RAGDefender-targeted discourse-diverse rewrites.} Objective: reduce
cross-passage similarity concentration so the poison set stops being the densest
subgraph.

\textit{FilterRAG-targeted low-overlap rewrites.} Objective: preserve the false
claim while lowering query and answer keyword overlap and raising unique-word
count.

\textit{ML-FilterRAG clean-reference rewrites.} Objective: move the learned
feature vector toward the clean feature distribution using clean passages as
stylistic references.

\subsection{Reproducibility Controls}
\label{subsec:repro}
\begin{itemize}
  \item Cached retrieval and cached defense scoring, so a rerun reproduces prior
        numbers exactly rather than approximately.
  \item Hashed and committed GPT prompt packets for every mutation family.
  \item Replacement-only poison budget: $N=\Npoison$ preserved in every mutated
        condition; no original-plus-mutated duplication.
  \item Held-out query identifiers fixed in advance for the confirmation set.
  \item No API calls in the test suite; every evaluation script consumes
        committed artifacts and loads models read-only.
  \item Self-query versus cross-query poison accounted separately, so a case that
        retrieves poison authored for a different pool query is never counted as
        if all retrieved poison targeted the case at hand.
\end{itemize}

\subsection{Poisoning Budget and Top-$k$}
\label{subsec:budget}
% Carried forward near-verbatim from the notes file: the strongest existing
% paragraph. Unicode quotes replaced with ASCII; citations to be added.
We set $N=\Npoison$ poisoned passages per target query to match the PoisonedRAG
default setting~\cite{zou2025poisonedrag}. We evaluate $k=5$ and $k=\Ktop$ to
separate two retrieval regimes. The $k=5$ setting corresponds to the PoisonedRAG
default and represents a poison-saturated context in which the number of
retrieved passages equals the number of injected poisoned passages. The
$k=\Ktop$ setting probes a mixed clean/poison regime where $k > N$, which
PoisonedRAG's own ablation identifies as the point where clean retrieved passages
enter the context while poisoned passages are still usually retrieved. This mixed
regime is particularly important for post-retrieval defenses such as RAGDefender
and FilterRAG, because their filtering decisions depend on the composition of the
retrieved top-$k$ set. The $k=5$ regime also violates RAGDefender's stated
requirement that at least one benign passage be retrieved, which is why
$k=\Ktop$ is the regime used for all stress-testing regimes above the nominal
one.

\subsection{Metrics}
\begin{itemize}
  \item \textit{Removed poison} and \textit{removed clean}: counts of retrieved
        poisoned and clean passages the defense removes.

  \item \textit{Self-query versus cross-query poison}: retrieved poisoned passages
        authored for this query versus for a different pool query, reported
        separately.

\subsection{RQ3: Do targeted text rewrites weaken passage filters?}
\label{subsec:rq3}
Regime: fixed retrieved context, poison text rewritten, development set of
$\NdevQ$ queries. \COMPLETED{development-set result}

Generic rewrites produce modest effects and serve as the negative control:
rewriting per se does not evade these filters. Among the targeted families, the
FilterRAG-targeted low-overlap family produces the strongest cross-defense
effect, weakening FilterRAG and transferring to the ML-FilterRAG-top-$k$ proxy;
the ML-FilterRAG clean-reference family moves only its own target; and the
RAGDefender-targeted family does not move RAGDefender at all. The asymmetry is
the finding: the density-based assumptions are text-reachable under hand-authored
rewriting and RAGDefender's clustering assumption, which the oracle of
Sec.~\ref{subsec:rq2} breaks reliably, is not.

how often it is reachable.

\subsection{RQ5: Does generation-time aggregation change the outcome?}
\label{subsec:rq5}
Regime: answer generation on shortlisted full-retrieval cases.
\COMPLETED{RobustRAG-KW shortlisted scale-up} \NOOVERCLAIM{shortlist only}

Table~\ref{tab:robustrag_kw_main} reports the $\NrrkwCases$ shortlisted cases.
RobustRAG-KW did not produce the attacker answer in 3 shortlisted cases where at
least one passage-filtering defense did. Two of those three outcomes are
abstentions and one is a clean defense, so the row counts of \texttt{Def.} and

same outcome for a user. RobustRAG-KW also failed on the cases where every

different signal than the passage filters, so it can hold where they fail and
fail where they hold. The $\NrrkwCases$ cases were shortlisted for filter stress
